# Capture One Ticket Creation Standard

This skill ensures that all new work items are properly documented and integrated into the project management system (Notion).

## 1. Context Gathering
- **Target Feature**: Identify the specific tool, engine component, or UI area to be reconstructed.
- **Sprint Selection**: Identify the active or target Sprint in the `Sprints` database (ID: `6360db11-ba37-82bb-bc58-81e475e8da56`).
- **Research**: Perform a quick `grep_search` on `RawDumps/` to identify key symbols related to the task to include in the plan.

## 2. Ticket Properties
- **Database**: `Tickets` (ID: `b970db11-ba37-8351-bf14-01025baf506e`).
- **Issue**: Concise title (e.g., "Implement Luma Curve Engine").
- **ID**: Unique ID (Automatically generated by Notion, e.g., `ID-11`).
- **Type**: `Feature Request`, `Bug`, `Improvement`, or `New Requirement`.
- **Priority**: `Low`, `Medium`, `High`, or `Critical`.
- **Sprints**: Relation to the selected Sprint ID.
- **Status**: Default to `Not started`.

## 3. Mandatory Page Content Structure
Every ticket MUST contain the following sections in its page body:

### Demande
- A clear, bulleted list of the requirements.
- Include raw text from specs or user instructions.
- Define the "What" and the "Why".

### Plan
- **Technical Steps**: Step-by-step implementation guide.
- **Affected Files**: List of specific files to modify or create.
- **Symbol References**: Key classes/properties found in `RawDumps/`.
- **Validation**: How to verify the implementation (e.g., visual comparison, unit test, build check).

## 4. Execution Workflow
1. **Search Sprint**: Use `notion_search` or `query_database` to get the correct Sprint ID.
2. **Draft Content**: Prepare the Demande and Plan sections in Markdown.
3. **Create Entry**: Use `add_database_entry` with the properties and the drafted content.
4. **Verification**: Confirm the ticket appears correctly in Notion with the linked relation.
